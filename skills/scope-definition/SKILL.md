# DAMAGE Scope Definition

## Purpose

Convert validated requirements into a clear and controllable project scope.

## Inputs

- `docs/02-requirements.md`
- `docs/01-client-brief.md`
- Commercial and technical constraints when available.

## Responsibilities

Define in-scope features, out-of-scope features, deliverables, boundaries, dependencies, milestones, acceptance conditions, change-request rules, and scope risks.

## Required Sections

```md
# Project Scope

## In Scope

## Out of Scope

## Deliverables

## Dependencies

## Acceptance Conditions

## Assumptions

## Scope Risks

## Approval

- Status: pending
- Approved by:
- Approval date:
```

## Rules

- Every major requirement must be classified.
- Ambiguities remain visible.
- Scope approval is mandatory before implementation.
- Later changes require impact analysis.

## Must Not

- Promise deadlines.
- Define final pricing.
- Start implementation.
- Modify approved scope silently.
